# What was removed or adapted for the public version

The original tool read its input from a corporate Oracle database. This public
version keeps the same *shape* of the problem but none of the infrastructure.

| Aspect | Original (internal) | Public version |
|---|---|---|
| Data source | Oracle database, queried on demand | Local SQLite file generated by `data/generate_synthetic_data.py` |
| Connection | Corporate Oracle connection (client libraries and network configuration) | `sqlite3` read-only connection to a local file; no credentials |
| Query dialect | Oracle SQL (`DECODE`, `TO_DATE`, `TO_CHAR`) | SQLite SQL (`CASE`, `strftime`) |
| Schema | Internal HR system tables/columns and internal codes | Fictional tables `employee`, `department`, `employee_attribute` |
| Result set | One row per employment record, fetched with `fetchall` into a pandas `DataFrame` | Same |
| Entities / employers | Real organizations identified by code and by badge prefix | `ENTITY A/B/C` |
| Data | Real employee records | Synthetic (`Employee 001…`) |
| Distribution | Internal desktop use | Source code only |

## Preserved on purpose

- The columns the application expects from the query
  (`MATRÍCULA`, `NOME_FUNCIONÁRIO`, `CPF`, `PIS`, `FUNÇÃO`, `LOTAÇÃO`, `JORNADA`,
  `ADMISSÃO`, `RESCISÃO`, `EMPRESA`, `VÍNCULO`) — so the rest of the code is
  unchanged.
- The attribute table pattern: some fields (tax id, job title) were stored as
  key/value rows and required joining the same table more than once.
- A sentinel date for "no termination", converted to `ATIVO` in the query.
- An exclusion list for technical badges.
- The rule that the employer returned by the query has priority over the one
  inferred from the badge prefix.

## Removed

- Database host, service name, user and password, Oracle client files and the
  network configuration file.
- Real table, column and code names of the source system.
- Real names, badge numbers, CPF/PIS, departments and job titles.
- Generated reports built from real data.
- Historical/legacy versions of the script.
